The Resources API gives you full programmatic control over the items in your workspace. Use it to retrieve paginated lists of resources, create new records, apply updates, and permanently remove items you no longer need. All endpoints require a valid API key — write and admin operations additionally require the `write` or `admin` scope respectively.

---

## GET /resources — List resources

Returns a paginated list of resources in your workspace, ordered by creation date (most recent first). Use query parameters to narrow results by status or other attributes.

<ParamField query="status" type="string">
  Filter resources by status. One of: `active`, `archived`, `draft`.
</ParamField>

<ParamField query="page" type="integer">
  The page number to return. Defaults to `1`.
</ParamField>

<ParamField query="per_page" type="integer">
  The number of results per page. Defaults to `20`. Maximum is `100`.
</ParamField>

```bash
curl "https://api.example.com/v1/resources?status=active&page=1&per_page=20" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

## POST /resources — Create a resource

Creates a new resource in your workspace. Requires the `write` scope.

<ParamField body="name" type="string" required>
  The name of the resource. Must be between 1 and 255 characters.
</ParamField>

<ParamField body="description" type="string">
  A longer description of the resource. Supports plain text up to 10,000 characters.
</ParamField>

<ParamField body="status" type="string">
  The initial status of the resource. One of: `active`, `archived`, `draft`. Defaults to `draft`.
</ParamField>

<ParamField body="owner_id" type="string">
  The ID of the workspace member to assign as the resource owner.
</ParamField>

<ParamField body="metadata" type="object">
  An optional key-value map of custom attributes to associate with the resource.
</ParamField>

```bash
curl -X POST https://api.example.com/v1/resources \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Q1 Planning Document",
    "description": "Consolidated planning notes for Q1 objectives and key results.",
    "status": "active",
    "owner_id": "user_abc123",
    "metadata": {
      "department": "engineering",
      "quarter": "Q1-2024"
    }
  }'
```

```json
{

    "name": "Q1 Planning Document",
    "description": "Consolidated planning notes for Q1 objectives and key results.",
    "status": "active",
```

## PUT /resources/{id} — Update a resource

Replaces the fields of an existing resource. All writable fields you include overwrite the current values; fields you omit are left unchanged. Requires the `write` scope.

<ParamField path="id" type="string" required>
  The unique identifier of the resource to update.
</ParamField>

<ParamField body="name" type="string">
  A new name for the resource.
</ParamField>

<ParamField body="description" type="string">
  Updated description for the resource.
</ParamField>

<ParamField body="status" type="string">
  Updated status. One of: `active`, `archived`, `draft`.
</ParamField>

<ParamField body="owner_id" type="string">
  Reassign the resource to a different workspace member.
</ParamField>

<ParamField body="metadata" type="object">
  A replacement key-value map of custom attributes. This overwrites the existing metadata entirely.
</ParamField>

```bash
curl -X PUT https://api.example.com/v1/resources/res_abc123 \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"status": "archived", "name": "Q1 Planning Document (Archived)"}'
```

```json
{
  "data": {
    "id": "res_abc123",
    "name": "Q1 Planning Document (Archived)",
    "description": "Consolidated planning notes for Q1 objectives and key results.",
    "status": "archived",
    "owner_id": "user_abc123",
    "metadata": {

      "quarter": "Q1-2024"
    },
    "created_at": "2024-01-15T10:30:00Z",

  },
  "error": null,
  "meta": {
    "request_id": "req_bcd890"

}
```

## DELETE /resources/{id} — Delete a resource

Permanently deletes a resource from your workspace. This action is irreversible. Requires the `admin` scope. A successful deletion returns `204 No Content` with an empty body.

<ParamField path="id" type="string" required>
  The unique identifier of the resource to delete.
</ParamField>

```bash
curl -X DELETE https://api.example.com/v1/resources/res_abc123 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

<Warning>
  Deleting a resource is permanent and cannot be undone. Consider updating the resource's status to `archived` instead if you want to retain a record without making it active.
</Warning>
