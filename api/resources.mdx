The Tasks API is the core of the Google REST API. Every task you see in the web app — whether it's a quick to-do or a complex work item with assignees, labels, and deadlines — can be created, read, updated, and deleted programmatically. Use the rich filtering capabilities on the list endpoint to build task reports, trigger automations based on status transitions, or synchronize Google tasks with an external project management tool.

---

## GET /tasks — List tasks

Returns a paginated list of tasks. Use query parameters to filter the results by project, status, assignee, or due date range. Tasks are ordered by creation date, most recent first.

<ParamField query="project_id" type="string">
  Filter tasks to a specific project by its ID.
</ParamField>

<ParamField query="status" type="string">
  Filter by task status. One of: `todo`, `in_progress`, `in_review`, `done`.
</ParamField>

<ParamField query="assignee_id" type="string">
  Filter tasks assigned to a specific user by their ID.
</ParamField>

<ParamField query="due_before" type="string">
  Return only tasks with a due date before this ISO 8601 timestamp (for example, `2024-03-31T23:59:59Z`).
</ParamField>

<ParamField query="due_after" type="string">
  Return only tasks with a due date after this ISO 8601 timestamp.
</ParamField>

<ParamField query="page" type="integer">
  The page number to return. Defaults to `1`.
</ParamField>

<ParamField query="per_page" type="integer">
  The number of results per page. Defaults to `20`. Maximum is `100`.
</ParamField>

```bash
curl "https://api.example.com/v1/tasks?project_id=proj_def456&status=in_progress&page=1" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```json
{
  "data": [
    {
      "id": "task_xyz789",
      "title": "Review Q1 report",
      "status": "in_progress",
      "project_id": "proj_def456",
      "assignee_id": "user_abc123",
      "due_date": "2024-01-31T17:00:00Z",
      "labels": ["finance", "urgent"],
      "created_at": "2024-01-15T10:30:00Z"
    }
  ],
  "error": null,
  "meta": {
    "page": 1,
    "per_page": 20,
    "total": 1
  }
}
```

## POST /tasks — Create a task

Creates a new task in your workspace. Requires the `write` scope.

<ParamField body="title" type="string" required>
  The title of the task. Must be between 1 and 255 characters.
</ParamField>

<ParamField body="project_id" type="string" required>
  The ID of the project to add this task to.
</ParamField>

<ParamField body="description" type="string">
  A longer description of the task. Supports plain text up to 10,000 characters.
</ParamField>

<ParamField body="assignee_id" type="string">
  The ID of the workspace member to assign the task to.
</ParamField>

<ParamField body="due_date" type="string">
  The due date and time in ISO 8601 format (for example, `2024-03-15T17:00:00Z`).
</ParamField>

<ParamField body="status" type="string">
  The initial status of the task. One of: `todo`, `in_progress`, `in_review`, `done`. Defaults to `todo`.
</ParamField>

<ParamField body="labels" type="array">
  An array of label strings to attach to the task (for example, `["backend", "high-priority"]`).
</ParamField>

```bash
curl -X POST https://api.example.com/v1/tasks \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Review Q1 report",
    "description": "Go through the finance team Q1 report and provide feedback.",
    "project_id": "proj_def456",
    "assignee_id": "user_abc123",
    "due_date": "2024-01-31T17:00:00Z",
    "status": "todo",
    "labels": ["finance", "urgent"]
  }'
```

```json
{
  "data": {
    "id": "task_xyz789",
    "title": "Review Q1 report",
    "description": "Go through the finance team Q1 report and provide feedback.",
    "status": "todo",
    "project_id": "proj_def456",
    "assignee_id": "user_abc123",
    "due_date": "2024-01-31T17:00:00Z",
    "labels": ["finance", "urgent"],
    "created_at": "2024-01-15T10:30:00Z"
  },
  "error": null,
  "meta": {
    "request_id": "req_vwx234"
  }
}
```

Returns the full detail of a single task, including its comment count and all metadata.

<ParamField path="id" type="string" required>

## PATCH /tasks/{id} — Update a task

Updates one or more fields on an existing task. Only include the fields you want to change — all other fields remain unchanged. Requires the `write` scope.

<ParamField path="id" type="string" required>
  The unique identifier of the task to update.
</ParamField>

<ParamField body="title" type="string">
  A new title for the task.
</ParamField>

<ParamField body="description" type="string">
  Updated task description.
</ParamField>

<ParamField body="status" type="string">
  Updated status. One of: `todo`, `in_progress`, `in_review`, `done`.
</ParamField>

<ParamField body="assignee_id" type="string">
  Reassign the task to a different workspace member.
</ParamField>

<ParamField body="due_date" type="string">
  A new due date in ISO 8601 format.
</ParamField>

<ParamField body="labels" type="array">
  A replacement array of label strings. This overwrites the existing labels entirely.
</ParamField>

```bash
curl -X PATCH https://api.example.com/v1/tasks/task_xyz789 \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"status": "in_review", "due_date": "2024-02-07T17:00:00Z"}'
```

```json
{
  "data": {
    "id": "task_xyz789",
    "title": "Review Q1 report",
    "status": "in_review",
    "project_id": "proj_def456",
    "assignee_id": "user_abc123",
    "due_date": "2024-02-07T17:00:00Z",
    "labels": ["finance", "urgent"],
    "created_at": "2024-01-15T10:30:00Z",
    "updated_at": "2024-01-17T09:00:00Z"
  },
  "error": null,
  "meta": {
    "request_id": "req_bcd890"
  }
}
```

## DELETE /tasks/{id} — Delete a task

Permanently deletes a task and all its associated comments. This action is irreversible. Requires the `admin` scope. A successful deletion returns `204 No Content` with an empty body.

<ParamField path="id" type="string" required>
  The unique identifier of the task to delete.
</ParamField>

```bash
curl -X DELETE https://api.example.com/v1/tasks/task_xyz789 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

<Warning>
  Deleting a task is permanent and cannot be undone. All comments and activity history associated with the task are also deleted. Consider updating the task's status to `done` instead if you want to archive it without losing data.
</Warning>
