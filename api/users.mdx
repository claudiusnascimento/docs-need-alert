The Users API gives you full programmatic control over your workspace's membership. You can retrieve a paginated list of all members, look up an individual user's profile, send invitations to new collaborators, update a member's role as their responsibilities change, and remove users when they leave your organization. All endpoints require a valid API key — write and admin operations additionally require the `write` or `admin` scope respectively.

---

## GET /users — List all members

Returns a paginated list of all members in your workspace, ordered by the date they joined (most recent first).

<ParamField query="page" type="integer">
  The page number to return. Defaults to `1`.
</ParamField>

<ParamField query="per_page" type="integer">
  The number of results per page. Defaults to `20`. Maximum is `100`.
</ParamField>

```bash
curl https://api.example.com/v1/users?page=1&per_page=20 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```json
{
  "data": [
    {
      "id": "user_abc123",
      "name": "Ada Lovelace",
      "email": "ada@example.com",
      "role": "admin",
      "joined_at": "2024-01-10T08:00:00Z"
    },
    {
      "id": "user_def456",
      "name": "Grace Hopper",
      "email": "grace@example.com",
      "role": "member",
      "joined_at": "2024-01-12T09:30:00Z"
    }
  ],
  "error": null,
  "meta": {
    "page": 1,
    "per_page": 20,
    "total": 2
  }
}
```

## GET /users/{id} — Get a specific user

Returns the profile of a single workspace member by their unique identifier.

<ParamField path="id" type="string" required>
  The unique identifier of the user to retrieve (for example, `user_abc123`).
</ParamField>

```bash
curl https://api.example.com/v1/users/user_abc123 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```json
{
  "data": {
    "id": "user_abc123",
    "name": "Ada Lovelace",
    "email": "ada@example.com",
    "role": "admin",
    "joined_at": "2024-01-10T08:00:00Z"
  },
  "error": null,
  "meta": {
    "request_id": "req_jkl012"
  }
}
```

## POST /users/invite — Invite a new member

Sends an email invitation to a new workspace member. The invitation expires after 7 days. Requires the `write` scope.

<ParamField body="email" type="string" required>
  The email address of the person you want to invite.
</ParamField>

<ParamField body="role" type="string" required>
  The role to assign when the invitation is accepted. One of: `owner`, `admin`, `member`, `viewer`.
</ParamField>

```bash
curl -X POST https://api.example.com/v1/users/invite \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "new.teammate@example.com",
    "role": "member"
  }'
```

```json
{
  "data": {
    "token": "invite_mno345",
    "email": "new.teammate@example.com",
    "role": "member",
    "expires_at": "2024-01-22T10:00:00Z"
  },
  "error": null,
  "meta": {
    "request_id": "req_pqr678"
  }
}
```

<Info>
  If the invited email address already belongs to a workspace member, the API returns a `409 Conflict` error. Use `PATCH /users/{id}` to update an existing member's role instead.
</Info>

## PATCH /users/{id} — Update a user's role

Updates the role of an existing workspace member. Requires the `admin` scope. You cannot demote the last `owner` in a workspace.

<ParamField path="id" type="string" required>
  The unique identifier of the user to update.
</ParamField>

<ParamField body="role" type="string" required>
  The new role to assign. One of: `owner`, `admin`, `member`, `viewer`.
</ParamField>

```bash
curl -X PATCH https://api.example.com/v1/users/user_def456 \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"role": "admin"}'
```

```json
{
  "data": {
    "id": "user_def456",
    "name": "Grace Hopper",
    "email": "grace@example.com",
    "role": "admin",
    "joined_at": "2024-01-12T09:30:00Z"
  },
  "error": null,
  "meta": {
    "request_id": "req_stu901"
  }
}
```

## DELETE /users/{id} — Remove a user

Removes a member from the workspace. Their tasks and contributions are preserved, but they lose access immediately. Requires the `admin` scope. A successful deletion returns `204 No Content` with an empty body.

<ParamField path="id" type="string" required>
  The unique identifier of the user to remove.
</ParamField>

```bash
curl -X DELETE https://api.example.com/v1/users/user_def456 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

<Note>
  Removing a user does not delete their account — it only revokes their access to your workspace. They can still log in to any other workspaces they belong to.
</Note>
