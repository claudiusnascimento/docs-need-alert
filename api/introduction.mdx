The Google REST API lets you build powerful integrations on top of your workspace data. Whether you're automating task creation from an external system, syncing members from your identity provider, or embedding productivity data into your own dashboards, every capability available in the web app is accessible through this API. All endpoints follow REST conventions and communicate exclusively over HTTPS.

## Base URL

Every API request you make must be directed to the following base URL. All endpoints described in this reference are relative to it.

```text
https://api.example.com/v1
```

## Request Format

Send all request bodies as JSON. Include the `Content-Type: application/json` header on every `POST`, `PUT`, and `PATCH` request, and include your API key in the `Authorization` header on every call. Query parameters are plain URL-encoded strings and do not require a content type.

```bash
curl https://api.example.com/v1/tasks \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"title": "My new task", "project_id": "proj_abc123"}'
```

## Response Format

Every response from the API — success or failure — is returned as a JSON object. The top-level envelope always contains three keys:

| Key | Type | Description |
|-----|------|-------------|
| `data` | object \| array \| null | The primary payload of the response. `null` on errors. |
| `error` | object \| null | Present only when the request fails. Contains `code` and `message`. |
| `meta` | object | Pagination cursors, rate-limit context, and request metadata. |

Here is an example of a successful response:

```json
{
  "data": {
    "id": "task_xyz789",
    "title": "Review Q1 report",
    "status": "todo",
    "created_at": "2024-01-15T10:30:00Z"
  },
  "error": null,
  "meta": {
    "request_id": "req_abc123",
    "page": 1,
    "per_page": 20,
    "total": 1
  }
}
```

And an example of an error response:

```json
{
  "data": null,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The field 'title' is required."
  },
  "meta": {
    "request_id": "req_def456"
  }
}
```

## Rate Limits

The API enforces per-minute rate limits based on your plan. Exceeding the limit returns a `429 Too Many Requests` response.

| Plan | Requests per minute |
|------|-------------------|
| Free | 100 |
| Pro | 1,000 |

Every API response includes the following headers so you can track your consumption in real time:

| Header | Description |
|--------|-------------|
| `X-RateLimit-Limit` | The maximum number of requests allowed per minute on your plan. |
| `X-RateLimit-Remaining` | The number of requests remaining in the current window. |
| `X-RateLimit-Reset` | Unix timestamp indicating when the current window resets. |

<Tip>
  If you are building a high-volume integration, check `X-RateLimit-Remaining` proactively and implement exponential backoff when you receive a `429` response. Upgrading to the Pro plan raises your limit tenfold.
</Tip>
