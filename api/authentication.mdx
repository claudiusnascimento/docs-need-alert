Google uses API keys to authenticate every request you make to the REST API. An API key is a long-lived credential tied to your account that grants access to your workspace data according to the scopes you assign it. You can create multiple keys — for example, one per integration or environment — and revoke any of them independently without affecting the others.

## Generating an API Key

<Steps>
  <Step title="Open API Keys settings">
    Log in to your Google workspace, click your avatar in the top-right corner, and navigate to **Settings > API Keys**.
  </Step>
  <Step title="Create a new key">
    Click **Generate Key** in the upper-right corner of the API Keys page.
  </Step>
  <Step title="Name and scope your key">
    Enter a descriptive name (for example, `production-integration` or `ci-pipeline`) and select the scopes this key requires. Choose the least-privileged scopes that satisfy your use case.
  </Step>
  <Step title="Copy and store your key">
    Your new API key is displayed **once**. Copy it immediately and store it in a secure location such as a secrets manager or encrypted environment variable. You will not be able to retrieve the full key value again after closing this dialog.
  </Step>
</Steps>

<Warning>
  Never embed your API key directly in client-side code, commit it to a public repository, or share it in chat or email. If a key is compromised, revoke it immediately from **Settings > API Keys** and generate a replacement.
</Warning>

## Using Your API Key

Pass your API key as a Bearer token in the `Authorization` header of every request. No session cookie or additional authentication step is required.

```text
Authorization: Bearer <YOUR_API_KEY>
```

Here is a complete example using curl:

```bash
curl https://api.example.com/v1/tasks \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Replace `YOUR_API_KEY` with the key you generated in the previous step. If you omit the header or supply an invalid key, the API returns a `401 Unauthorized` response.

## Key Scopes

When you generate a key, you assign it one or more scopes that control what operations it can perform. Always grant the minimum scopes necessary for your integration.

| Scope | Permissions |
|-------|-------------|
| `read` | Read-only access to all resources — list and retrieve workspaces, projects, tasks, and members. |
| `write` | All `read` permissions, plus the ability to create and update resources. |
| `admin` | All `write` permissions, plus the ability to delete resources and manage workspace settings and members. |

<Info>
  Scopes are additive. A key with the `write` scope implicitly includes all `read` permissions. You do not need to select both.
</Info>

## Error Responses

If authentication or authorization fails, the API responds with one of the following HTTP status codes:

| Status | Code | Cause |
|--------|------|-------|
| `401 Unauthorized` | `UNAUTHORIZED` | The `Authorization` header is missing, malformed, or contains an invalid or revoked API key. |
| `403 Forbidden` | `FORBIDDEN` | The API key is valid but lacks the required scope to perform the requested operation. |

A `403` response means your key authenticated successfully but does not have permission for the action. Update the key's scopes in **Settings > API Keys**, or generate a new key with the required scope.

```json
{
  "data": null,
  "error": {
    "code": "FORBIDDEN",
    "message": "This API key does not have the 'admin' scope required to delete resources."
  },
  "meta": {
    "request_id": "req_ghi789"
  }
}
```
