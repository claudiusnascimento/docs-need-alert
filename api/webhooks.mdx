Webhooks let your application react to events in Google as they happen, without polling the API. When a subscribed event occurs — such as a task being created or a member being added — Google sends an HTTP `POST` request to the URL you specify, carrying a signed JSON payload that describes the event. This makes webhooks the foundation of event-driven integrations, real-time dashboards, and cross-tool automations.

## Supported Events

You can subscribe to any combination of the following events when registering a webhook. Each event name follows the pattern `resource.action`.

| Event | Triggered when… |
|-------|----------------|
| `task.created` | A new task is created in any project in your workspace. |
| `task.updated` | A task's title, description, status, due date, or labels are changed. |
| `task.deleted` | A task is permanently deleted. |
| `task.assigned` | A task is assigned or reassigned to a workspace member. |
| `project.created` | A new project is created in your workspace. |
| `project.updated` | A project's name, description, or settings are changed. |
| `member.added` | A new member accepts an invitation and joins the workspace. |
| `member.removed` | A member is removed from the workspace. |

## Registering a Webhook

You can register a webhook through the Google interface or directly through the API.

### Via the Google UI

<Steps>
  <Step title="Open Webhook settings">
    Log in to your Google workspace and navigate to **Settings > Webhooks**.
  </Step>
  <Step title="Add a new webhook">
    Click **Add Webhook** in the upper-right corner.
  </Step>
  <Step title="Configure your endpoint">
    Enter the full HTTPS URL of your endpoint in the **URL** field (for example, `https://yourapp.com/webhooks/google`). Your endpoint must be publicly reachable and must respond to Google's delivery requests with a `2xx` status code.
  </Step>
  <Step title="Select events">
    Choose the events you want to subscribe to from the list. You can select individual events or use **Select All** to receive every event type.
  </Step>
  <Step title="Save and verify">
    Click **Save**. Google will send a test ping to your endpoint to confirm it is reachable. Once verified, your webhook is active.
  </Step>
</Steps>

### Via the API

To register a webhook programmatically, send a `POST` request to `/webhooks`. Requires the `write` scope.

```bash
curl -X POST https://api.example.com/v1/webhooks \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://yourapp.com/webhooks/google",
    "events": ["task.created", "task.updated", "member.added"]
  }'
```

```json
{
  "data": {
    "id": "wh_abc123",
    "url": "https://yourapp.com/webhooks/google",
    "events": ["task.created", "task.updated", "member.added"],
    "secret": "whsec_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
    "created_at": "2024-01-15T10:00:00Z"
  },
  "error": null,
  "meta": {
    "request_id": "req_efg345"
  }
}
```

<Note>
  The `secret` field is returned only once when the webhook is created. Store it securely — you will use it to verify the signature of every incoming payload.
</Note>

## Webhook Payload

Every event delivery is an HTTP `POST` request to your endpoint with a `Content-Type: application/json` body. Here is an example payload for a `task.created` event:

```json
{
  "event": "task.created",
  "timestamp": "2024-01-15T10:30:00Z",
  "workspace_id": "ws_abc123",
  "data": {
    "id": "task_xyz789",
    "title": "Review Q1 report",
    "status": "todo",
    "project_id": "proj_def456",
    "assignee_id": "user_ghi012",
    "created_at": "2024-01-15T10:30:00Z"
  }
}
```

The `event` field tells you which event occurred, `timestamp` is the UTC time of the event, `workspace_id` identifies the source workspace, and `data` contains the full resource object relevant to that event type.

## Verifying Webhook Signatures

<Warning>
  Always verify the webhook signature before processing any payload. Skipping this check means your endpoint could process forged or replayed requests from untrusted sources.
</Warning>

Every delivery includes an `X-Webhook-Signature` header containing an HMAC-SHA256 digest of the raw request body, signed with the `secret` you received when you created the webhook. Compute the expected digest on your server and compare it to the header value. Reject the request if they do not match.

<Tabs>
  <Tab title="Node.js">
    ```javascript
    const crypto = require("crypto");

    function verifyWebhookSignature(rawBody, signatureHeader, secret) {
      const expectedSignature = crypto
        .createHmac("sha256", secret)
        .update(rawBody, "utf8")
        .digest("hex");

      const trusted = Buffer.from(`sha256=${expectedSignature}`, "utf8");
      const received = Buffer.from(signatureHeader, "utf8");

      // Use timingSafeEqual to prevent timing attacks
      if (trusted.length !== received.length) {
        return false;
      }
      return crypto.timingSafeEqual(trusted, received);
    }

    // Express.js example
    app.post("/webhooks/google", express.raw({ type: "application/json" }), (req, res) => {
      const signature = req.headers["x-webhook-signature"];
      const isValid = verifyWebhookSignature(req.body, signature, process.env.WEBHOOK_SECRET);

      if (!isValid) {
        return res.status(401).send("Invalid signature");
      }

      const event = JSON.parse(req.body);
      console.log("Received event:", event.event);

      res.status(200).send("OK");
    });
    ```
  </Tab>
  <Tab title="Python">
    ```python
    import hmac
    import hashlib

    def verify_webhook_signature(raw_body: bytes, signature_header: str, secret: str) -> bool:
        expected_signature = hmac.new(
            secret.encode("utf-8"),
            raw_body,
            hashlib.sha256
        ).hexdigest()

        expected = f"sha256={expected_signature}"

        # Use compare_digest to prevent timing attacks
        return hmac.compare_digest(expected, signature_header)


    # Flask example
    from flask import Flask, request, abort
    import json, os

    app = Flask(__name__)

    @app.route("/webhooks/google", methods=["POST"])
    def handle_webhook():
        raw_body = request.get_data()
        signature = request.headers.get("X-Webhook-Signature", "")
        secret = os.environ["WEBHOOK_SECRET"]

        if not verify_webhook_signature(raw_body, signature, secret):
            abort(401)

        event = json.loads(raw_body)
        print(f"Received event: {event['event']}")

        return "OK", 200
    ```
  </Tab>
</Tabs>

<Tip>
  Always read the raw, unparsed request body before passing it to the signature function. Parsing the body as JSON first can change whitespace and key ordering, causing a valid signature to fail verification.
</Tip>

## Retry Policy

If your endpoint fails to respond with a `2xx` status code — or does not respond within 10 seconds — Google treats the delivery as failed and retries it automatically.

Failed deliveries are retried **3 times** with exponential backoff:

| Attempt | Delay after previous failure |
|---------|------------------------------|
| 1st retry | 1 minute |
| 2nd retry | 5 minutes |
| 3rd retry | 30 minutes |

If all three retries fail, the delivery is marked as permanently failed and no further attempts are made. You can review delivery history and manually replay failed events from **Settings > Webhooks > [Your Webhook] > Delivery Log**.

<Note>
  Because retries can result in duplicate deliveries (for example, if your server processed the request but responded too slowly), design your event handler to be **idempotent**. Use the combination of `event`, `timestamp`, and `data.id` as a unique key to detect and safely ignore duplicate deliveries.
</Note>
